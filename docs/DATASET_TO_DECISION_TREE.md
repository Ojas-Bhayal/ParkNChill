# What Loading a Dataset Does to the Decision Tree

## The short version

**Loading a dataset does not train or change the Decision Tree.** It prepares eligible, labelled slot examples that can be used for training. The existing tree remains the active model until the user clicks **Train Decision Tree** or separately loads a compatible `.pncmodel` file.

## The four different actions

1. **Load Dataset (PKLot)**
   - Reads parking photographs and matching XML annotations.
   - Uses XML geometry and labels for each slot.
   - Extracts the current ten-feature vector under `v2.3-10feat-enhanced-v1` / `ivp-enhance-v1` and records source provenance.
   - Assigns or preserves capture-group partition labels.
   - Displays valid images, valid slots, occupied/available balance, invalid records, detector failures, and partition/group counts.
   - Does **not** fit a new tree, edit old tree thresholds, or evaluate a newly trained model.

2. **Train Decision Tree**
   - Uses eligible ten-feature labelled records from the dataset mode currently selected.
   - For PKLot, it trains only on `TRAIN`, selects parameters using `VALIDATION`, and reports performance on the frozen `TEST` partition.
   - For the reviewed-slots workflow, it uses the grouped split generated by that path; it must not be represented as camera-independent unless the source groups are actually disjoint.
   - If prerequisites fail, no new tree is confirmed. The UI reports the reason.

3. **Save Trained Decision Tree**
   - Serializes the currently active compatible tree and its feature-schema/preprocessing metadata to `.pncmodel`.
   - It does not save the entire PKLot archive or replace the dataset.

4. **Load Saved Decision Tree**
   - Activates a previously trained compatible model.
   - It does not add training examples or retrain the tree. Loading a different model clears the previous model's evaluation report so stale metrics cannot be shown as that model's performance.

## What each visible count means

- **Valid images**: source photographs successfully accepted by the importer.
- **Valid slots**: slot annotations that passed import validation.
- **Eligible samples (all partitions)**: records compatible with the active ten-feature schema and accepted provenance policy. This is not the same as the number used to fit the tree.
- **Occupied / Available**: class distribution across the eligible active dataset.
- **TRAIN / VALIDATION / TEST rows and groups**: eligible samples and independent capture groups assigned to each partition.
- **Active tree**: the tree currently used for Decision Tree predictions. It can be an older compatible model even after a new dataset is loaded; dataset loading alone does not retrain it.
- **Evaluation results**: metrics from the most recent evaluation still associated with the current in-memory model. When the dataset or model changes, old results should not be presented as results for the new combination.

## Correct workflow

1. Choose **PKLot Dataset** or **My Reviewed Slots** in the Dataset selector.
2. Click **Load Dataset (PKLot)...** to import PKLot, or review slots to create human-verified records.
3. Read the dataset-impact panel. Confirm eligible count, both classes, partition/group counts, schema, and the stated next action.
4. If it says **DATA NOT READY** or **training is blocked**, fix the reported prerequisite. Do not bypass it by treating provisional predictions as labels.
5. Click **Train Decision Tree**. Wait for the success/failure status.
6. Open **View Results** and inspect partition size, confusion matrix, and metrics. If the test set is too small or non-independent, metrics should be shown as unavailable rather than as a persuasive percentage.
7. Save the newly trained tree if appropriate. To compare a loaded tree with the current detector result, return to **Review Slots** and click **Run Tree Separately**. It fills the **Loaded Tree Prediction** column without replacing the last analysis result, detector suggestions, occupancy summary, or overlays. Only select **Feature Decision Tree** mode and click **Detect and Analyse** if you intentionally want the tree output to become the primary result.

## Dataset constraints

The complete PKLot archive is external and does not need to be included in the project ZIP. A smaller subset can be used during development, but it should contain multiple independent camera/date groups and both occupancy classes in the training partition. Keep all slots from one photograph, and preferably related images from one camera/date capture group, in the same partition to reduce leakage.

The bundled legacy eight-feature demonstration CSV is not compatible training evidence for the enhanced ten-feature schema. Do not relabel it as enhanced data or use its historical demo metrics as accuracy for the current model.
